# tianzhi-classics

中华术数典籍的结构化数据集。

## 概述

术数典籍中的取用规则是确定的、可枚举的：《穷通宝鉴》以十天干配十二月令，列出
一百二十格调候取用；《子平真诠》就八格分别指明顺用逆用、相神与忌神；《三命通会》
《协纪辨方书》载各神煞的起例。这些规则数百年来以文字形式流传，本数据集将其整理
为机器可读的结构化数据。

数据随 [tianzhi-core](https://github.com/zaoxu001/tianzhi-core) 发布，算法直接
据此计算，计算结果携带出处标签，可逐条回溯至对应条目。

## 数据来路

一份数据是怎么来的，与它是什么同样要紧。本仓每份数据在 `catalog.json` 中标有
`provenance`：

| 来路 | 含义 | 现有 |
| --- | --- | --- |
| `extracted` | 自原书文本逐条提取、清洗、标注条目位置 | 7（《穷通宝鉴》120 格、《滴天髓》4 篇、《子平真詮》8 格、《神峰通考》1 篇、《三命通會》2 条、《欽定協紀辨方書》2 条、《古今圖書集成》1 条） |
| `packaged` | 库中随包的既有数据，提取与校勘过程未见记载，未回原书逐条复核 | 3 |
| `derived` | 自算法实现的常量导出，常量注释标明典籍出处，部分引有原文成句 | 8 |
| `modeled` | 自算法实现的判断逻辑结构化而来，非自原书文本提取 | 2 |

`modeled` 一类需特别说明。`bazi/ditian-rules.json` 所载，是本实现如何理解《滴天髓》
论从象、化象、通关这几条法则——条件、动作、阈值——**不等同于原书论述**。原书于此
另有大段论说与例证，未纳入。`bazi/shenfeng-rules.json` 同理。

### 校勘所见

《穷通宝鉴》一百二十格已逐格回原文核对，`bazi/entries/qiongtong.json` 于每格记
原文关键句、今译、自原文读出的取用、现有数据的取用，并判归四档：

| 判归 | 含义 | 格数 |
| --- | --- | --- |
| `agree` | 原文与现有数据相同 | 65 |
| `data_ok` | 数据所多之字另有依据（见该月后文或该季总论） | 50 |
| `text_wins` | 当以原文为准：数据有缺，或次序与原文相反 | 4 |
| `suspect` | 存疑待核 | 1 |

`text_wins` 四格：甲日午月（原文「庚金次之」而数据未收庚）、甲日未月与申月
（原文「先丁后庚」而数据以庚居首）、乙日未月（原文「丙火为尊」而数据以癸居首）。
调候讲先后，次序并非无关紧要。

`suspect` 一格：甲日戌月，数据作「甲庚」。庚有据，见「癸庚决不可少也」；然「甲」
为日干自身，不当为自身之调候用神，疑系该段「譬如木为犁，能疏季土」中「木为犁」
之喻被误录。已记存疑，未擅改数据——改算法所用之数据，须经核定。

《滴天髓》四条已回原文核对：从象、化象出「從化論－真」，通关出「通隔論」，另记
「從化論－假」一条（论假从假化，本实现未涉及）。算法注释所引的四句原文皆在该本
中一一找到。

需注意分篇之异：算法的出处标签作「从象」「化象」「通关」，系《滴天髓阐微》一系
的分篇；本次所据维基文库本分篇作「從化論－真」「通隔論」。条目以算法标签为键，
另记该本实际篇名，两边都对得上。

《子平真詮》维基文库无此条目，改据**中国国家图书馆藏本影印件**核对（Wikimedia
Commons，PD-old）：《秘本子平真詮》山陰沈孝瞻撰，民國萬海世界圖書館發行，序署
乾隆四十一年。逐字核对书葉十七【論用神】一篇，核出四处异文：

| 处 | 底本 | 算法注释 | 判 |
| --- | --- | --- | --- |
| 印格 | 刧**財**以護印 | 劫**才**以護印 | 「才」为「財」之俗写，术数书中常见，非讹 |
| 阳刃格 | **羊**刃喜官煞以制伏 | **陽**刃喜官煞以制伏 | 二名古今通用，底本从「羊」 |
| 伤官格 | 傷官喜佩印**神**制伏 | 傷官喜佩印**以**制伏 | 底本字迹稍漫，未能确指，存疑 |
| 月劫格 | ……透食以化**劫** | 同 | 末字略漫，以文义当为「化劫」，存疑 |

存疑二处照实标注，未擅改。本书其余各篇（論陽刃、論建祿月劫等）尚未核对。

该底本的权利状况已逐层核实，记于 `bazi/entries/ziping.json` 的 `meta.rights`：
原作为清人所撰，早入公有领域；民國排印本属法人作品，依中国著作权法发表后五十年
届满，1999 年已过期；影印件为机械扫描，不产生新的著作权（Commons 挂 PD-scan、
PD-China）。本仓仅摘录八句原文用以标注出处，今译系自撰，全书未转载。

顺带一提：维基文库的录入文本为 CC BY-SA，带署名与传染性要求；国图影印本是纯
公有领域，无附带义务。就本仓的用途而言，用影印本反比用维基文库干净。

《神峰通考》已核：所引「有病方为贵，无伤不是奇；格中如去病，财禄两相随」在该本
「病药说类」中一字不差。原书上下文比那一句更有分量——张楠自述「未谙病药之说，
屡以中和而究人之造化，十无一二有验；后始得悟病药之旨……则尝八九而得其妙」，
一并录入。

余下三部受阻于底本，情形各异，已记入 `catalog.json` 的 `verify_log`，下次接手
不必从头再查：

| 书 | 受阻之处 |
| --- | --- |
| 淵海子平 | 该本页首自注「此文档未完成」，七十三篇中无文昌一节；其中「天德」「月德」仅顺带提及，无起例 |
| 協紀辨方書 | 维基文库无此书，四庫全書本亦缺页。天德月德待另寻底本 |

《三命通會》先前也在此列——维基文库另有一个只录九卷的本子，九卷全扫皆无天乙一节。
后改用**四庫全書本**卷三，「論天乙貴人」一节核到，所引口诀一字不差。同名之书版本不同，
录入的完整程度也不同，核对时须记明所据何本。

该条比口诀本身更值得记的是：原书并非叫人死背歌诀，而是讲推法——贵人按天干五合定位，
遇辰（天罗）、戌（地网）则跳过，「甲戊庚牛羊，六辛逢馬虎」是推出来的结果。这一层
一并录入。

同卷另核到文昌贵的起例，**与本站所用不是一派**：十干中仅甲、戊相合，余八干皆异。
本站用的是「食神之临官位」一路。两说并立，非讹误，未据此改动算法。

两部仍受阻的，其起例规则依旧在用（`derived`，自算法常量导出，注释里录着口诀），
只是未能回原书复核，故不升为 `extracted`。

### 两次失手，都在书名上

《協紀辨方書》我两度报称「维基文库无此书」，其实是漏了「欽定」二字——条目作
《欽定協紀辨方書 (四庫全書本)》，三十六卷俱在，卷五「義例三」正是天德月德的专章。
二十四条（十二月 × 天德、月德）与本站数据逐条核对，全合。

《渊海子平》那条则是出处本身记错了。文昌贵人的起例原记作出自该书，而维基文库那个
本子自注「此文档未完成」，七十三篇中并无文昌一节。改从《古今图书集成》艺术典星命部，
口诀与推法俱全。

两次的教训是一样的：**核不到先别急着说书里没有，多半是没找对名字或没找对本子。**

## 链回原文

出处标签指到条目一级，原文链接也应当指到同一级，否则「可查证」只是说说而已。

`bazi/ref-anchors.json` 给出拼接方法。以《穷通宝鉴》为例，该版本的章节分到季为止，
无分月的标题，故一个锚点统辖一季三个月：

```
锚点 = {季}{日干}{日干五行}

辛日午月  午属三夏，辛属金  →  三夏辛金
甲日寅月  寅属三春，甲属木  →  三春甲木

https://zh.wikisource.org/wiki/穷通宝鉴#三夏辛金
```

文件内附月支到季、天干到五行的映射表。一百二十格拼出的锚点已逐个比对页面实有的
`id`，无一落空。

其余各书的锚点粒度尚未逐一核验，只给全书链接。

## 数据结构

### 调候取用 `bazi/tiaohou.json`

日干 → 月令 → 所取天干，按首要程度排序。

```json
{ "辛": { "午": ["壬", "己", "癸"] } }
```

### 喜忌与大运 `bazi/jinbuhuan.json`

日干 → 月令 → 条目。

```json
{ "辛": { "午": { "xi": ["壬"], "ji": ["丁"],
                  "dayun_xi": ["亥", "子", "寅", "卯"],
                  "dayun_ji": ["申", "酉"],
                  "note": "喜根深" } } }
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `xi` | string[] | 喜用天干 |
| `ji` | string[] | 忌见天干 |
| `dayun_xi` | string[] | 大运顺行的地支 |
| `dayun_ji` | string[] | 大运逆行的地支 |
| `note` | string | 原书附注 |

### 格局顺逆 `bazi/geju-ops.json`

格名 → 条目。

```json
{ "财格": { "name": "财格", "mode": "顺",
            "generate": ["食神"], "protect": ["正官"],
            "taboo": ["比肩", "劫财"],
            "note": "财喜食神以相生，生官以护财；忌比劫分夺",
            "source": "子平真诠·论用神" } }
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `mode` | string | `顺` 或 `逆`。善者顺用，不善者逆用 |
| `generate` | string[] | 相生之神 |
| `protect` | string[] | 护卫之神 |
| `taboo` | string[] | 忌见之神 |
| `note` | string | 该条的依据 |
| `source` | string | 出处 |

`bazi/geju-alias.json` 为格名别称至正名的映射。

### 取用法则 `bazi/ditian-rules.json` `bazi/shenfeng-rules.json`

并非所有典籍的内容都是查表形态。《滴天髓》论从象、化象、通关，《神峰通考》论
病药，讲的是「什么条件下该怎么取」，条目形如条件与动作。

```json
{ "从象": {
    "source": "滴天髓·从象",
    "quote": "从得真者只论从，从神又有吉和凶。",
    "applies_to": "取用",
    "rules": [
      { "name": "从弱",
        "when": ["同党占比低于 follow_weak_ratio", "日主无强根"],
        "then": "不扶日主，从其旺神（取泄、耗、克日主者中最旺的一行）" }
    ],
    "thresholds": {
      "follow_weak_ratio": { "value": 0.12, "from": "本包取值，可调" }
    } } }
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `source` | string | 出处 |
| `quote` | string | 原文成句；未引原文者为空，另以 `quote_note` 说明 |
| `applies_to` | string | 该法则作用于哪一环 |
| `rules[].when` | string[] | 全部成立方才适用 |
| `rules[].then` | string | 成立后如何取用 |
| `thresholds` | object | 判别所用的数值 |
| `thresholds.*.from` | string | 该数值的来历。标「本包取值」者为工程取值，非典籍所定 |

典籍言理不言数，落到可计算的程序上必须给出具体阈值。`from` 字段把两者分开：
哪些是书上说的，哪些是本包定的，不相混淆。这些阈值与代码同源，由 `tools/check.py`
核对。

### 神煞起例 `bazi/shensha-*.json`

以所查之干或支为键，落处为值。

```json
{ "甲": ["丑", "未"] }
```

### 干支基础 `bazi/ganzhi.json`

单文件多表，键为表名。

| 表 | 形状 | 说明 |
| --- | --- | --- |
| `jiazi` | string[60] | 六十甲子，自甲子起 |
| `gan_wuxing` `zhi_wuxing` | 干支 → 五行 | |
| `hidden` | 地支 → [[干, 位]] | 藏干，位为 `本`／`中`／`余` |
| `changsheng` | string[12] | 十二长生次第 |
| `gan_he` `zhi_liuhe` | [{pair, into}] | 合为无序一对，`into` 为合化之行 |
| `zhi_chong` `zhi_hai` | 地支 → 地支 | |
| `yangren` | 阳干 → 地支 | 阴干是否有刃各家分歧，此处只列阳刃 |
| `wangxiang` | string[5] | 旺相休囚死 |

### 人元司令 `bazi/siling.json`

月支 → 依次司令的天干与所占日数。

```json
{ "丑": [ { "gan": "癸", "days": 9 },
          { "gan": "辛", "days": 3 },
          { "gan": "己", "days": 18 } ] }
```

## 使用

```bash
pip install tianzhi-core
```

```python
from tianzhi_core.bazi import tiaohou

tiaohou.climate_gods("辛", "午")
# ClimateGods(day_gan='辛', month_zhi='午', gans=('壬', '己', '癸'),
#             primary='壬', elements=('水', '土'), source='穷通宝鉴')
```

亦可直接读取本仓 JSON，或读取随包分发于 `tianzhi_core/data/` 的同一份数据。

算法输出的每条判据均带出处标签，格式为「书名·条目」：

```
穷通宝鉴·辛日午月      日干与月令即条目坐标
子平真诠·论用神        篇名即条目坐标
```

## 校验

数据在本仓与 tianzhi-core 各有一份，前者是数据集的发布形态，后者是算法运行时
实际读取的那份。两份分处两个仓库，需定期校验，以免漂移。

```bash
python tools/check.py
```

随包的三份逐字节比对；其余几张表由算法常量导出，脚本重新导出后比对；取用法则
两份的条文是人写的，机器无从比对，但其中的阈值逐项核对——阈值一漂，数据上写的
判据就不是算法实际在用的判据。脚本并会反查本仓是否有文件漏在清单之外。

一致则退出码 0，否则逐项列出差异。

## 许可

数据部分为公有领域古籍中的规则，不构成受著作权保护的表达：条目内容为事实性
对应关系，编排体例出自原书。

现代点校本、白话译注及今人解读不在收录范围。

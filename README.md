# 天秩典籍 · tianzhi-classics

[天秩](https://tianzhi.live)算法的数据来源：从东方术数典籍提取的结构化规则表，
以及算法的哪一条对应书里的哪一格。

天秩（[tianzhi-core](https://github.com/zaoxu001/tianzhi-core)）不凭空造规则。
每一条有出处的判据都出自下面这些书，这个仓库把出处记下来，让结论可以回溯查证。

著作权在整理者与出版方手里。

## 收的是规则表，不是原文

这是本仓最要紧的一条，也是它跟「古籍全文库」的区别。

这里存的是**从原书提取的结构化规则**，例如：

```json
{ "辛": { "午": ["壬", "己", "癸"] } }
```

读作「辛日生于午月，调候取壬、己、癸」。

这样做有两个理由，先说实际的那个：规则表能直接跟算法对上。算法照着它算，页面照着
它显示，同一份数据，不会出现「书上写一套、算出来另一套」。原文做不到这件事——
原文是给人读的，不是给程序查的。

另一个理由是干净。著作权保护的是**表达**，不保护**事实与方法**。「辛日生午月取
壬己癸」是一条规则，谁来写都是这几个字，不构成独创的表达；而按十干乘十二月编排
是原书就有的体例，也不是现代整理者的贡献。所以规则表不牵涉任何人的著作权。反过来，
现代点校本的断句与校勘是有可能构成作品的，所以那些一概不取。

原文本身不在这里转载，只在 `ref` 字段给一条参考链接，想读原文的自己去读。

## 锚点：算法怎么指回原文

`anchors` 说明一部书的条目用什么方式定位：

| 取值 | 含义 | 用在 |
| --- | --- | --- |
| `gan-month` | 日干 × 月令，120 格 | 穷通宝鉴、金不换大运 |
| `chapter` | 按篇目 | 其余 |

两类都不用人工建映射表，因为出处本来就带在算法的输出里：

```
geju.month_pattern()  → evidence 含「子平真诠·论用神」      篇名即锚点
yongshen.select()     → evidence 含「穷通宝鉴·辛日午月」    干支即坐标
```

## 分门别类

术数不止八字。`modules` 列出门类，每部书用 `module` 归到其中一门。现在只有八字
一门收齐了，六壬、奇门、紫微、六爻、梅花的位置先留着，`ready` 为假。

## 目录

```
catalog.json      书目：元数据、归属门类、规则表位置、原文参考链接
texts/<slug>.json 原文摘录的位置，眼下空着（见上「收的是规则表，不是原文」）
```

规则表本身随 `tianzhi-core` 发布，见 `catalog.json` 每部书的 `rules` 字段，
例如 `tianzhi_core/data/tiaohou.json`。放在那边而不是这边，是因为算法要用它，
让数据跟着用它的代码走，才不会有两份各自漂移的副本。

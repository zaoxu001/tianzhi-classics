# 天秩典籍 · tianzhi-classics

把中华术数典籍整理成结构化数据。

《穷通宝鉴》成书四百年，讲的是十天干生在十二个月令分别该取哪几个字，一共一百二十格。
四百年来这一百二十格只以文字的形式存在——要用它，人得自己翻书、自己记、自己查。
《金不换大运》另有一百二十格的喜忌与大运顺逆，《子平真诠》有一整套格局的成败规则，
《三命通会》有几百条神煞的定义。

这些规则本身是确定的、可查的、能逐条对照的，但从来没有人把它们变成机器能读的数据。

这个仓库做这件事。

## 数据长什么样

《穷通宝鉴》「辛日生于午月，调候取壬、己、癸」这一格：

```json
{ "辛": { "午": ["壬", "己", "癸"] } }
```

《金不换大运》同一格，多了不该碰什么，以及大运走哪些地支：

```json
{ "辛": { "午": { "xi": ["壬"], "ji": ["丁"],
                  "dayun_xi": ["亥", "子", "寅", "卯"],
                  "dayun_ji": ["申", "酉"], "note": "喜根深" } } }
```

一百二十格都是这个形状，可以查询、可以比对、可以直接喂给程序。

## 只整理规则，不转载原文

这里存的是规则，不是原书的文字。

原因有两条。实际的那条：规则能直接跟算法对上，算法照着它算，页面照着它显示，
同一份数据不会出现「书上写一套、算出来另一套」；原文做不到这件事，它是给人读的，
不是给程序查的。

另一条是干净。著作权保护的是表达，不保护事实与方法——「辛日生午月取壬己癸」是一条
规则，谁来写都是这几个字。而现代点校本的断句与校勘、白话译注、今人解读则可能构成
作品，所以一概不取。想读原文的，`catalog.json` 里每部书都附了参考链接。

## 怎么用

规则表随 [tianzhi-core](https://github.com/zaoxu001/tianzhi-core) 一起发布，装上就能用：

```bash
pip install tianzhi-core
```

```python
from tianzhi_core.bazi import tiaohou
tiaohou.climate_gods("辛", "午")     # 辛日午月该取什么
```

算法算出来的每一条判据都带着出处，例如「穷通宝鉴·辛日午月」「子平真诠·论用神」，
可以逐条回到这里对照——这是术数少见的东西：结论可以被检验。

`catalog.json` 是书目本身：每部书的来历、归在哪一门、规则表在哪、原文参考链接。
